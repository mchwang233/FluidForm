# 聊天的会话和上下文（2026-11-22）

## 为什么

API 模型的对话原来把"发过的原文"存下来，每轮拍平成一条用户消息重发：

- 开场时的人设、附件全文、上一个模型的旧对话永远留在第一条里（裁剪时特意保留第一条）。一段真实对话里
  94% 是三天前的一份日志，每条消息约 7.5 万 token。
- 带工具时 system 是写代码代理的提示词，聊天规则只是用户消息里的一段；改了规则，老对话也不会变。
- 会话永不过期。

参考：OpenClaw 的会话、压缩、系统提示（docs/concepts/session、compaction、system-prompt），DeepSeek 的多轮消息格式。

## 改动

规则在聊天包（`server/packages/chat/chat.mjs`，1.1.0），本体只做管道：

| 层 | 规则 | 在哪 |
|---|---|---|
| 会话 | 来自自动化的对话闲置 2 小时、或过了当天 4 点，开新的；`/new`、`/reset`、"新对话"随时开。旧对话留在记录里，长期记忆不动 | `chat.session`；`automations.ts` |
| system | 每轮现拼：人设、它是谁、能做什么、在哪怎么说话。不放别人说过的话 | `chat.dialogue` |
| messages | 从对话记录现拼：记忆和摘要作为开头的背景，然后是最近的原话（正常的多轮消息） | `chat.history`、`chat.dialogue` |
| 时间 | 只放在这一轮的消息前，之前的内容不变，缓存能命中 | `chat.dialogue` 的 `now` |
| 附件（文本、文件） | 当轮给全文；之后只留名字和对话文件夹里一份副本的路径 | `attachments.copiesIn` |
| 图片 | 最近 8 轮内最新的 2 张每轮真的带上，放在原来那条消息里；更早的只注明"当时看过"，不给路径（读文件工具显示不了图片）。带图期间只选能看图的模型 | `picturesShown`、`chat.showsPictures` |
| 压缩 | 未摘要的原话超过 2.4 万字，答完后在后台摘要，留最近 1.2 万字；摘要失败时最多发 4 万字 | `chat.compaction`；`leading.ts` |

会员 CLI 自己保存会话，仍是第一条带人设（`chat.opening`）。任务的负责人不受影响。以前存下的原文不删，
只是不再发送。

## 节奏（第 2、3 步）

| 情况 | 怎么办 | 在哪 |
|---|---|---|
| 收到消息 | 立刻贴"敲键盘"；0.8 秒内的连发合成一条；按到达顺序交给本体 | 机器人包 `Typing`、`Gather`、`InOrder` |
| 还没出字、没用工具时又来一条 | 停下前一条，两条一起答；同样的话只算一次 | `chat-turns.ts` |
| 已经出字或在用工具时又来一条 | 排在后面；排着的几条合成一条 | `chat-turns.ts` |
| 群里另一个人说话 | 不打断，排队 | 按"会话 + 人"分轮次 |
| `/stop`、`/new`、`/status` | 不经过模型，立刻答；停下时连正在跑的命令一起停，卡片就地收尾 | `capability-runner.ts`、`agent.ts` |
| 等图 | 只有明确指着图说（这张、图里、看看截图）才等，最多 8 秒 | `PICTURE_WORDS` |
| 思考强度 | 闲聊、只发一张图 low；干活、要想的、长消息、带文件、对着图提问 high | `effortFor` |
| 流式卡片 | 一张卡片，积压时只显示最新的内容 | 机器人包 `Reply` |

## 图片为什么要重发（2026-11-22 晚）

第 1 步上线当晚：发一张苍鹭的照片，答对了；接着问"这是什么鸟"，请求里已经没有图，历史里却写着"要看就用工具再读
这个路径"，工具回答"Read does not show pictures"，模型于是说自己看不了图、上一条是瞎猜的。所以图片和文本附件
分开处理。请求大小的估算（预算预留、限流、压缩）把每张图按 12 KB 文本算，不按 base64 的长度算（`boundBytes`）。

## 在聊天里开始任务、收到做出的文件（2026-11-23）

- 聊天里排的任务，回复「开始」就开工，「取消」就不做了（单独一条；群里要 @ 它）。只有让它排的人能这样做：
  私聊里就是那个人，群里按飞书的 open_id 认人（`origin.requester`）。网页上的确认照旧。没有等着的任务时，
  「开始」就是一句普通的话。按计划自带的预算上限跑，默认 $2。
- 任务结束时，结果里提到的、在任务自己文件夹里真实存在的文件（链接、路径、反引号里的名字、表格里的文件名都算；
  最多 5 个、每个不超过 20 MB；文档、表格、演示、图片、压缩包在前，脚本在后）作为文件发到原来的消息下面
  （`task-files.ts`）。发出的文字只有结果开头的结论（遇到标题或表格就停），完整结果作为「结果说明.md」一起发；
  文字里不出现这台机器的路径（`withoutPaths`）。
- 聊天每次作答前，把它排过的、已结束的任务做出的这些文件复制到聊天文件夹的 `tasks/<任务>/`，并告诉模型在那里：
  说「发给我」时它直接发，不会以为丢了再排一遍（2026-11-23 的 PPT 就是这样被重排的）。
  这些文件的名字写在每条消息前那一行里（不只在系统提示里说有个文件夹）：只说"在 tasks/ 里"时，低思考强度的回答
  不去看，照着自己先前说的"没留下来"又说了一遍。
- 排任务只带最近 3 条消息里的文件，不再带整段聊天的全部附件。
- 计划排好后由 FluidForm 说一次怎么开始，模型自己不再宣布。
- 每条消息前的"现在"一行带上这条用的模型和思考强度；看图规则写明图能留多久。

## 风险

- 上一轮工具的输出不带到下一轮，只带回答；要细节时模型重新查。
- 摘要会丢细节，完整记录仍在对话里。
- 思考强度按关键词判断，会有判错的：判低了答得浅，判高了慢一点。
- 会员 CLI 不流式，答完之前都算"还没开始"，期间来新消息会打断它。
- 打断时已经发出的请求可能照样计费，用量不一定记得到。
