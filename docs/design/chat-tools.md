# 聊天里的小事自己做

## 为什么

聊天原来只能聊。问一句"北京天气怎么样"，模型手上没有任何工具，只能说"我拿不到实时天气"。
要它查，就得排成任务、等主人确认、打开联网，查个天气走这一套太重。

所以把事情分成两类：

- **小事**：查天气、汇率，打开一个链接看看，算一笔账，处理一两个小文件。聊天里的模型当场做完，不用批准。
- **大事**：写程序、做成套的文档、改用户的项目、长时间的调研。照旧排成任务，等主人确认。

## 改动

- **设置**（`config.py`）：
  - `chat_tools` 开关，默认关。
  - `chat_tools_network`：命令能不能联网，默认关。
  - `chat_tool_seconds`、`chat_tool_turns`：每条消息的上限，默认 120 秒、20 次工具调用。
- **`supervisor.chat_tools(run)`**：一段聊天能不能动手，能的话在哪里动手。
  - 没有项目文件夹的聊天：用 `<workspace_root>/<folder_id>` 这个专属文件夹，可读可写，按设置决定能否联网。
  - 带项目的聊天：只读项目，不给工具。
  - 开关关着：不给工具。
- **`supervisor.ask` → `providers.converse(tools=…)`**：
  - **API 模型**：用步骤那一套工具（`act=True`），包括 Bash、Read、Write、Edit、Glob、Grep、LS。
    - 工作目录就是那个文件夹；
    - 沙箱规矩和步骤一样：看不到主目录和 FluidForm 的数据，碰不到本机服务；
    - 每条消息用 `max_turns` 限次数、`wait_for` 限时间；
    - 超时就停下，回一句"这件事 N 秒内没做完……可以把它排成任务"。
  - **会员 CLI**：不变，还是只聊天。
- **给模型的说明**（`supervisor.chat_tools_note`，放在 `chat_role` 里）：
  - 告诉它小事当场做，以及能用什么工具、在哪个文件夹、能不能联网、上限是多少。
  - 举例：查天气用 `curl wttr.in`。
  - 大事怎么办：飞书等自动化的聊天里写 TASK 行（见 capability-packages.md），网页聊天里告诉用户可以转成任务。
  - 没查过的东西不许说查过。
  - 机器上已有的能力（`capabilities.section()`）一并列出；每条消息点到的工具对应的技能（`skills.for_step`）附在那条消息后面，和步骤的做法一样。
- **花费**：照常记在这段聊天上。飞书聊天的花费计入自动化当天的额度。

## 测试

- `test_chat.py`：
  - 打开开关后，API 模型的聊天拿到专属文件夹，可以联网，上限按设置，说明写进了开头；
  - 带项目的聊天不给工具；
  - 开关默认关；
  - 会员 CLI 回答的聊天没有工具说明；
  - 飞书聊天的说明提到 TASK 行；
  - 超时会停下并说明，`converse` 用 `act`、`max_turns`、`network` 和那个文件夹调用模型。

## 风险

- **聊天能联网跑命令**：这和打开联网的任务一样。默认关，由这台机器的设置打开。沙箱照样看不到主目录、FluidForm 的数据和本机服务。
- **不用批准**：靠每条消息的次数和时间上限、当天额度来兜底。要做大事，模型应该提出任务；它判断错了，最多就是这两分钟、这几次调用。
- **超时停下时**：已经花掉的那部分 token 没有记账，因为调用被中途打断，拿不到用量。
