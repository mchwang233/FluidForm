# 聊天里的动作用工具调用；记住聊天里的人

## 为什么

聊天让 FluidForm 做事，原来靠模型在回答末尾写一行字：`TASK:`、`SEND:`、`ENGINEER:`，再由正则把它读出来。模型格式写错、JSON 断成两行，或者把这一行写在了句子中间，就会漏掉或者误触发。主流的做法是用模型原生的工具调用。

另外，飞书里的人说过的偏好（"回答短一点"、"我是做前端的"），只留在当前这段聊天的历史里。换了模型、开了新的一段聊天，就都忘了。

## 改动

- **`chat_actions.py`**（新），开关 `chat_action_tools`，默认关：
  - 有工具的聊天（`supervisor.chat_tools`，只有 API 模型）多几个工具：`StartTask`、`SendFile`、`CallEngineer`，开了 `user_memory` 时还有 `Remember`、`Forget`。网页聊天只有 `CallEngineer`。
  - 每次调用记成它代表的那一行，加在回答末尾（`Providers.converse`）。之后照原来的方式读：只有一个地方做决定，CLI 模型照旧写这几行。
  - 一次回答最多一个任务、最多发 5 个文件。
  - 提示词告诉模型："用这些工具，不用写那几行"。
- **`remembering.py`**（新），开关 `user_memory`，默认关：
  - 自动化的聊天可以写 `REMEMBER: <谁>: <一句话>`、`FORGET: <那条里的词>`。这几行不给人看（`ACTION_LINE`）。
  - 按会话存在自动化的状态里（`state["memory"]`），每个会话最多 30 条，每条最多 300 个字符；看着像密码或密钥的不存。
  - 这个会话新开一段聊天时（换了模型，或第二天），先把记住的内容告诉它（`remembering.told`）。
  - 记下的内容会写进这个自动化的日志。

## 测试

- `test_chat_actions.py`：
  - 工具调用会变成它代表的行，按原来的方式读出任务、文件和平台工程师调用；
  - 人看不到这几行；
  - 回答以外不提供工具，调用也无效；
  - 哪种聊天拿到哪些工具。
- `test_capability_packages.py`：
  - 记下的内容不给人看，密码不存；
  - 新开的聊天会被告知记住的内容；
  - `FORGET` 能删掉一条。

## 风险

- 记错了：模型可能把一时的话当成了长期偏好。内容在自动化日志里能看到，用户说一句"忘掉……"就能删。
- 群聊里的"成员N"只是同一个会话里的称呼，换一个群就对不上同一个人。
